# Feature verification

The **academic brief** column summarizes the project claims supplied for this audit. The final academic PDF was unavailable, so the comparison uses the brief as design context and the repository as the implementation source.

**Verified** indicates the scoped behavior was exercised or established directly by repository evidence. **Partially Verified** indicates a working path with an implementation gap or untested variants. **Unverified** indicates an external or environment-dependent capability without a successful execution. **Not Implemented** indicates the claimed workflow or technique has no current implementation.

| Feature | Academic brief | Source | Verification method | Status | Known limitations |
| --- | --- | --- | --- | --- | --- |
| Authentication and role-based access | Student and administrator sign-in with role-specific access | [Accounts](../accounts/views.py), [dashboards](../dashboard/views.py), [academic guards](../academics/views.py), [POS guards](../pos/views.py) | Exercised both role logins, a cross-role redirect, and plan ownership checks. Reviewed decorators. | Partially Verified | First-login password enforcement is inconsistent across direct workflow routes. Guest handling in POS checks the role before authentication. |
| Student registration and management | Register and manage student accounts | [Academic views](../academics/views.py), [student import](../academics/student_import_services.py), [email tests](../academics/tests_email.py) | Traced manual registration and list. Confirmed a CSV import and in-memory welcome email on PostgreSQL. | Partially Verified | The custom portal offers create, import, and list. Editing and deletion are available through permissioned Django admin. `.xlsx` was untested and legacy `.xls` needs an additional reader. |
| Curriculum import and management | Create and import curricula and their courses | [Academic forms](../academics/forms.py), [import service](../academics/upload_services.py) | Ran CSV parser tests and exercised editable CSV preview and confirmation on PostgreSQL. Reviewed Excel, DOCX, and text-PDF branches. | Partially Verified | Layout and columns matter. `.xlsx`, DOCX and curriculum PDF were untested. Legacy `.xls` needs an additional reader. |
| Prerequisites and co-requisites | Manage dependency relationships and honor them when rearranging a plan | [Academic models](../academics/models.py), [forms](../academics/forms.py), [scheduler](../pos/services.py) | Reviewed create/list and import. Exercised a prerequisite-driven deferral. | Partially Verified | Requirements are shared by catalog course. Missing or cyclic dependencies can undermine scheduling, and same-term co-requisite placement is only enforced in one direction. |
| Manual grades and course records | Enter grades and process academic outcomes | [Academic views](../academics/views.py), [grade model](../academics/models.py), [tests](../academics/tests.py) | Verified passing and failing entries in a smoke test. Existing tests confirmed that manual entry blocks passed-course re-entry and permits failed-course re-entry. | Verified | Grades are student-entered. Upload confirmation does not apply the same pass lock. |
| Grade upload and OCR | Enter grades from uploaded documents | [Grade upload service](../academics/grade_upload_services.py), [academic views](../academics/views.py) | Existing parser and persistence tests passed. Exercised a synthetic text PDF through upload, preview, confirmation, and credit calculation. | Partially Verified | Scanned PDFs lack the text layer this branch requires. Image OCR needs Tesseract, which was unavailable for this audit. |
| Academic progress | Display completed, failed, and remaining courses and credit progress | [Progress service](../academics/services.py), [progress template](../templates/academics/academic_progress.html) | Rendered the progress page and student dashboard with a pass and a fail. Inspected the calculations. | Verified | Earned units sum passed records and can overcount multiple credited attempts. Standing counts recorded attempts regardless of grade. |
| Automated rearrangement | Produce a revised POS using grades, eligibility, offerings, and unit limits | [Scheduler](../pos/services.py), [plan models](../pos/models.py) | Exercised failed-course retake placement, prerequisite deferral, a credited pass exclusion, and generation of a new current draft. Inspected the other scheduling branches. | Partially Verified | No live offerings calendar or final feasibility pass. The 50-pass heuristic can leave conflicts and extend beyond curriculum years. |
| Generated plan review and comparison | Review the generated plan against the original POS | [Plan views](../pos/views.py), [detail template](../templates/pos/generated_pos.html) | Opened draft history and detail, verified that an original failed attempt and retake both appeared. | Partially Verified | The detail page presents original and rearranged rows together. A separate side-by-side comparison and student plan editor are absent. |
| PDF preview and download | Preview and download generated reports | [PDF response](../pos/pdf.py), [preview template](../templates/pos/pos_pdf_preview.html), [report template](../templates/pos/pdf/_pos_pdf_document.html) | Opened the HTML preview and rendered and inspected the one-page PDF attachment with synthetic data. | Verified | Requires native WeasyPrint libraries. The term summary counts rows where the template intends to total units. Multi-page layout was untested. |
| Graph traversal, priority queues, and stack-based operations | The brief describes graph-based dependency mapping, priority queues, and stack-based operations. | [Scheduler](../pos/services.py) | Inspected dependency representations, ordering, convergence, and persistence. | Not Implemented | Dependency adjacency maps exist. The scheduler uses repeated passes and sorted lists. No graph traversal or topological sort, priority queue, stack-based undo, or optimization solver was found. |
| Hosted deployment and live SMTP | Academic web application with downloadable reports | [Deployment files](../build.sh), [Procfile](../Procfile), [settings](../config/settings.py) | Reviewed deployment commands and SMTP configuration. Verified local PDF and in-memory mail. | Unverified | The Procfile target does not match the WSGI module. A hosted build, live SMTP delivery, and production configuration were outside the verification environment. |
